# Замер скорости скачивания

Консольный скрипт на Python для замера скорости скачивания.

## Цель

Принять URL, сделать к нему несколько последовательных HTTP-запросов, дождаться полного тела каждого ответа и посчитать среднее время запроса, общий объем скачанных данных и скорость загрузки.

## Требования

- Python 3.8 или новее
- Только стандартная библиотека (`urllib`). Дополнительные пакеты не нужны.

## Как запустить

```bash
python3 speed_test.py https://upload.wikimedia.org/wikipedia/commons/3/3f/Fronalpstock_big.jpg
```

Параметры:

| Параметр | Описание |
| --- | --- |
| `url` | Адрес, к которому стучаться |
| `-n`, `--count` | Число последовательных запросов (по умолчанию 10) |
| `--timeout` | Таймаут одного запроса в секундах (по умолчанию 60) |

Другие примеры:

```bash
python3 speed_test.py -n 5 --timeout 30 https://upload.wikimedia.org/wikipedia/commons/3/3f/Fronalpstock_big.jpg
python3 speed_test.py --help
```

При ошибке HTTP, сети или таймауте скрипт печатает сообщение в stderr и завершается с кодом 1. При некорректных аргументах код выхода - 2.

## Единицы измерения

- 1 МБ = 10^6 байт
- 1 Мбит = 10^6 бит
- Скорость выводится в Мбит/с и в МБ/с

Скрипт считает в десятичных единицах, принятых в сетях. Двоичные мебибайты (1 МиБ = 2^20 байт) в вывод не входят.

## Как считается скорость

- Среднее время запроса - сумма времен всех успешных запросов, деленная на их число.
- Общий объем - сумма размеров тел ответов в байтах.
- Скорость в МБ/с: `общий_объем / 10^6 / суммарное_время`.
- Скорость в Мбит/с: `общий_объем × 8 / 10^6 / суммарное_время`.

Во время каждого запроса входит установка соединения, получение заголовков и полное чтение тела ответа. Запросы выполняются строго последовательно: следующий стартует только после завершения предыдущего.

## Что можно доработать

1. Отдельно считать время до первого байта и время чтения тела, помимо полного времени запроса.
2. Добавить в сводку минимум, максимум, медиану и разброс по запросам.
3. Сохранять результаты прогона в JSON или CSV с датой, URL и скоростью, чтобы сравнивать каналы со временем.
4. В одном запуске обойти несколько URL и вывести сравнение скоростей рядом.
5. Добавить параметр, который сбрасывает кэш (уникальный query-параметр или заголовок), чтобы повторные запросы меньше опирались на кэш.
6. При ошибке одного запроса продолжать остальные и в итоге показать, какие прошли, какие нет.
7. Измерить также скорость отдачи (upload).
8. Опционально запускать несколько соединений параллельно и сравнить результат с последовательным режимом.
9. Привязать запросы к IPv4 или IPv6 и к выбранному сетевому интерфейсу.
10. Вывести прогресс длинной загрузки, чтобы было видно, что запрос еще идет.
